# הגדרה, הרצה ובדיקה — M1 + M1.1 (חיבור Supabase)

> שום דבר כאן לא פורס לייצור. הפריסה הקיימת (Netlify) לא משתנה עד שתמזג את הענף.

## 0. מה צריך במחשב
- Node.js 20 ומעלה (נבדק עם Node 24).
- בתיקיית הפרויקט: `npm install`

## 1. בדיקה מיידית — בלי שום חשבון חיצוני

### 1.1 האפליקציה החדשה במצב דמו
```
npm run dev
```
- במחשב: http://localhost:5173 → "פתיחה במצב דמו".
- **בטלפון** (באותה רשת Wi-Fi): בטרמינל יופיע `Network: http://192.168.x.x:5173` — פתחו את הכתובת הזו בטלפון.
  אם Windows שואל על חומת אש עבור Node.js — אשרו לרשת פרטית בלבד.
- במצב דמו הנתונים סינתטיים, נשמרים רק בדפדפן הנוכחי, ומסומנים בבאנר קבוע. הם לא מגיעים לשום שרת.

### 1.2 האפליקציה הקיימת (המתוקנת)
```
node scripts/static-server.mjs legacy 4173
```
- http://localhost:4173 — ו-`/backup.html` לכלי הגיבוי.
- שימו לב: כתובת מקומית היא "מקור" אחר מהאתר החי, לכן **הנתונים האמיתיים שלכם לא יופיעו כאן** (זה מכוון). לבדיקה עם Drive אמיתי צריך להוסיף את `http://localhost:4173` ל-Authorized JavaScript origins של ה-Client ID — לא חובה.

### 1.3 כל הבדיקות האוטומטיות
```
npm run typecheck
npx vitest run            # יחידה + בסיס נתונים (Postgres 17 משובץ, רץ מקומית)
npx playwright test       # דפדפן: אפליקציה קיימת + חדשה, מחשב + נייד
npm run build && npm run check:secrets
```

## 2. לפני כל דבר אחר: גיבוי הנתונים האמיתיים
הנתונים האמיתיים נמצאים בדפדפן שבו עבדתם ו/או ב-Google Drive (appDataFolder) — לא במאגר.
1. **לפני** מיזוג הענף, באתר החי הנוכחי — אין בו כלי גיבוי, לכן:
   - בכל דפדפן שבו השתמשתם: פתחו את האתר, F12 → Console, והריצו:
     `copy(localStorage.getItem('freelance_local'))` — ואז הדביקו לקובץ טקסט ושמרו.
     (בטלפון אין Console — הגיבוי ייעשה דרך `backup.html` אחרי המיזוג.)
2. **אחרי** מיזוג ופריסה: פתחו `https://<האתר>/backup.html` בכל דפדפן/מכשיר, הורידו את העותק המקורי, את דוח הביקורת, ואת קובץ ה-Drive (כפתור "התחבר וקרא מ-Drive").
3. הגרסה המתוקנת גם שומרת אוטומטית עותק "pre-upgrade" ב-IndexedDB בפעם הראשונה שהיא נפתחת, ועותקים לפני כל מיזוג.

## 3. חיבור ל-Supabase — פרויקט פיתוח (נתונים סינתטיים בלבד)

> פרויקט **פיתוח** נפרד. לא מעבירים אליו נתונים עסקיים אמיתיים, ולא מעלים אליו נתוני דמו.
> פרויקט הייצור ייפתח בנפרד בשלב המיגרציה, עם החלטה על תוכנית (Free / Pro).

### 3.1 תוכנית ועלות
| | Free | Pro |
|---|---|---|
| מחיר | 0 | ‎$25 לחודש |
| גיבוי אוטומטי | **אין** | יומי, 7 ימים |
| השהיה | מושהה אחרי שבוע ללא פעילות (אפשר להפעיל מחדש) | לא |
| פרויקטים פעילים | 2 | — |

(supabase.com/pricing, נבדק 5.11.2026.) לפיתוח — **Free מספיק לכל הבדיקות**. לא מפעילים מנוי בתשלום.

### 3.2 הכניסה: דוא״ל + סיסמה
שירות הדוא״ל המובנה של Supabase שולח רק **2 הודעות בשעה**, ורק לחברי הצוות של הפרויקט — לא מתאים לכניסה בקישור.
לכן הכניסה היא בדוא״ל וסיסמה, והחשבון נוצר ידנית בלוח הבקרה. אין הרשמה ציבורית.

### 3.3 צעדי ההקמה (מפורטים, צעד-צעד, בצ'אט)
1. פרויקט חדש: אזור **Central EU (Frankfurt)**, סיסמת DB חזקה במנהל סיסמאות.
   כל אזור באירופה מתאים (גם West EU / Ireland). מומלץ להשאיר **לא מסומן** את "Automatically expose new tables":
   המיגרציה נותנת הרשאות במפורש (GRANT) ומפעילה RLS על כל הטבלאות, ונבדקה גם במצב הזה.
2. **SQL Editor** → להריץ את המיגרציות **לפי הסדר**, כל קובץ ב-New query נפרד → Run:
   `supabase/migrations/20261105000000_m1_foundation.sql`, ואחריו `supabase/migrations/20261106000000_m2_payments_expenses.sql`.
   המיגרציה של M2 מוסיפה בלבד (לא משנה ולא מוחקת נתונים קיימים), ויוצרת גם את דלי הקבצים הפרטי `expense-files`.
   אחר כך: `supabase/checks/verify_access.sql` (קריאה בלבד) — כל 10 השורות צריכות להיות ✅.
3. **Authentication → Sign In / Providers**: לכבות את **Allow new users to sign up**.
   ⚠️ **לא** לכבות את ספק ה-Email עצמו — זה חוסם גם כניסה. (בבדיקות מקומיות זו בדיוק הטעות שנתפסה.)
   באותו מסך, תחת Email: אורך סיסמה מינימלי 10 (מומלץ).
4. **Authentication → Users → Add user → Create new user**: הדוא״ל שלך + סיסמה חזקה, **Auto Confirm**.
5. **Project Settings → API Keys**: להעתיק את ה-Project URL ואת ה-**Publishable key** (`sb_publishable_…`).
   **לא** את ה-Secret key. אם בטעות מוגדר מפתח secret/service_role — האפליקציה מסרבת להתחבר ומסבירה.
6. בתיקיית הפרויקט, קובץ `.env.local` (לא נכנס ל-Git):
   ```
   VITE_SUPABASE_URL=https://<ref>.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
   VITE_APP_ENV_LABEL=פיתוח
   ```
7. רשימת המורשים (SQL Editor) — ראו 3.4; בלי זה החשבון מחובר אבל לא רואה דבר.

### 3.4 חשבונות בדיקה אוטומטית (סינתטיים)
הבדיקות האוטומטיות לא משתמשות בסיסמה שלך. הן משתמשות בשני חשבונות בדיקה:
```
node scripts/live-dev-init.mjs <הדוא"ל שלך>
```
הסקריפט יוצר `.env.live.dev.local` (לא נכנס ל-Git) עם סיסמאות חזקות, ומדפיס:
- שתי כתובות: `<you>+fm-test-owner@…` (מורשה) ו-`<you>+fm-test-outsider@…` (**לא** מורשה — כדי לוודא שחשבון מחובר אבל לא מורשה לא רואה כלום);
- פקודת SQL לרשימת המורשים: הדוא״ל שלך + חשבון הבדיקה המורשה.

יוצרים את שני המשתמשים ב-Add user (Auto Confirm) עם הסיסמאות מהקובץ, ומריצים את ה-SQL.

### 3.5 הרצה ובדיקה
```
npm run dev              # מחשב: http://localhost:5173 · טלפון: כתובת ה-Network (192.168.x.x:5173)
npm run test:live:dev    # כל הבדיקות מול פרויקט הפיתוח (API + דפדפן, מחשב + טלפון מדומה)
```
בפס העליון: **☁ מחובר לענן · פיתוח** = נתונים בשרת; **מצב דמו · מקומי בלבד** = נתונים סינתטיים בדפדפן הזה בלבד.
בלי רשת מופיע **אין חיבור לרשת** ושום פעולה לא מוצגת כאילו נשמרה.

מגבלת Supabase: כ-30 כניסות ל-5 דקות מאותה כתובת IP. אם בדיקה נכשלת עם "יותר מדי ניסיונות" — להמתין 5 דקות ולהריץ שוב.

### 3.6 שרת Supabase מקומי (אופציונלי, דורש Docker Desktop)
אותם שירותים של Supabase (Auth, PostgREST, Postgres 17) רצים מקומית — כך נבדק הכל לפני שהיה פרויקט בענן.
```
npm run supabase:start          # מחיל את המיגרציות אוטומטית
npm run test:live:local:setup   # 3 חשבונות סינתטיים + רשימת מורשים, כותב .env.live.local
npm run test:live:local
npm run supabase:stop
```
הגדרות ה-Auth המקומיות (`supabase/config.toml`): הרשמה כבויה, סיסמה ≥ 10 עם אותיות וספרות.

### 3.7 קבצים מצורפים (הוצאות)
- הקבצים נשמרים בדלי **פרטי** `expense-files` ב-Supabase Storage, בתיקייה לפי מזהה המשתמש. אין קישור ציבורי;
  צפייה היא דרך קישור חתום שתקף 5 דקות. משתמש אחר, משתמש לא מורשה או גולש אנונימי — לא יכולים לקרוא, להעלות או למחוק.
- מקור שצורף אינו נמחק ואינו נדרס מהאפליקציה (תיעוד). תמונה או PDF בלבד, עד 10MB.
- בתוכנית החינמית: 1GB אחסון קבצים. מספיק לפיתוח; לייצור צריך להחליט על תוכנית וגיבוי.

## 4. מה עדיין לא נעשה בכוונה
- **אין פריסה.** כשתרצה: Netlify → Deploy Preview לענף (לא production), עם משתני הסביבה של 3.3 ב-Netlify UI.
- **ה-netlify.toml בענף** מגדיר `publish = "legacy"`. זה דורס את הגדרות ה-UI. לפני מיזוג: ודאו ב-Netlify (Site configuration → Build & deploy) שאין build command או תיקיית publish אחרת שאתם צריכים.
- **רוטציית ה-OAuth client secret** — לא בוצעה. הצעדים ב-`UPGRADE_SPEC.md` §9.3. האפליקציה לא משתמשת ב-secret כלל.
- **מיגרציית נתונים** מהאפליקציה הקודמת — שלב 2.
